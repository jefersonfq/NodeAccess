## Existing context

Inspect only relevant sources: `DESIGN.md`, global styles/tokens, layouts, component library, nearby screens for the same role, approved screenshots/Figma, and brand rules. Identify density, spacing rhythm, typography hierarchy, color roles, surfaces, navigation, forms, tables, dashboards, charts, motion, responsiveness, and anti-patterns.

Do not replace an established language merely to make a screen look newer.

## DESIGN.md contract

When broad work lacks a reliable contract, use the bundled template. Document product personality, roles, task/risk profile, density, typography, spacing, semantic colors, status, surface/border/radius/shadow, navigation, form/table/dashboard/chart/motion/responsive rules, approved references, and explicit anti-patterns.

Keep rules observable and implementable. Link standard screens/components. Update only when the team accepts a deviation as a reusable pattern.

## Reference-based design

From screenshots/mockups/Figma extract structure, hierarchy, rhythm, typography, color roles, component and interaction patterns, and responsive assumptions. Separate structural details from decoration.

Adapt references to actual workflow, data density, accessibility, performance, existing tokens, and components. Do not blindly reproduce them or guess missing tokens/assets/responsive behavior; document uncertainty.

## UX discovery

Record user/role, goal, decision, frequency, environment, risks, current path, costly errors, evidence, and assumptions. For broad or critical work, map current journey, pain points, opportunities, proposed journey, and unanswered questions.

Do not expose every backend field. Prioritize task completion, scanability, error prevention, and recovery.

## Direction exploration

Use alternatives only when justified. Directions must differ in information architecture or workflow, not decoration. Compare layout, grouping, density, navigation, CTA, progressive disclosure, tone, advantages, risks, and use case. Select and record one direction before architecture/implementation.
