# ACL: melhorias de experiência e diagnóstico

## Entrega

- Diagnóstico por ação: Visualizar, Conectar, Editar e Administrar aparecem com
  permitido/não permitido. Editar não é apresentado como equivalente a Conectar.
- Prévia efetiva: considera as demais concessões locais/herdadas de usuário,
  grupos e roles. Mostra quem ganha, mantém ou perde Conectar no item selecionado,
  com até dez exemplos e suas outras fontes. Contagens incluem todos os usuários
  ativos do principal; exemplos são limitados apenas na apresentação.
- Origem herdada: a tabela abre a pasta de origem quando o operador pode
  administrá-la. A autorização é calculada no backend e revalidada ao abrir.
- Busca de usuários por nome/e-mail no servidor, em páginas de 30. Não fica
  restrita aos primeiros 100 usuários. Há debounce, retry, retenção da seleção
  e proteção contra respostas antigas. Busca limitada ao tenant e a quem
  administra a ACL do item.
- Edição direta de regras locais: preenche principal e permissões; mantém a
  confirmação com snapshot e não cria regra duplicada.
- Meu acesso no menu do host: disponível também para usuário comum. Consulta
  somente o usuário autenticado, sem lista de usuários, membros ou ACL completa.
  Considera o requisito de gestão de hosts para administrar ACL e explica a
  diferença entre concessão ACL e disponibilidade dessa ação.

## Correção adicional

Ao retirar deliberadamente sua própria administração de ACL, o editor delegado
recebia erro após a alteração já estar salva: a releitura da lista exigia a
permissão recém-removida. A operação agora retorna sucesso sem devolver a ACL.
A tentativa seguinte de ler/administrar permanece bloqueada.

O teste com erro 503 também reproduziu um recarregamento global que apagava o
formulário de ACL. Essas operações autenticadas agora tratam a recuperação
localmente, com retry; continuam exigindo token e autorização. Erros 401 mantêm
o tratamento de autenticação. A bateria cobre 503 na prévia, busca e Meu acesso.

## Validar como usuário

1. Em `/hosts`, abra o menu da pasta corporativa e escolha Gerenciar permissões.
2. No diagnóstico, busque por nome/e-mail e confira cada ação separadamente.
   Use Carregar mais para percorrer os resultados.
3. Na ACL local, use Editar. Confirme que o principal e as permissões atuais
   estão preenchidos; a confirmação mostra a regra e o efeito restante no item.
4. Na ACL herdada, clique na origem autorizada para abrir a pasta correta.
5. Com usuário comum, abra o menu de um host visível e escolha Meu acesso.
   Não há seletor de outro usuário nem controles para modificar regras.

## Validação

```bash
npm run test:acl:core
npm run test:acl:mysql
FRONTEND_BASE=http://127.0.0.1:5177 npm run test:acl:web
```

Resultado local: 130 testes de backend/HTTP/classificação de erros e uma integração MySQL aprovados,
além dos fluxos de navegador em pasta, host e árvore corporativa. Typecheck
frontend/backend, build do pacote compartilhado e build de produção do frontend
foram validados. Os componentes novos passaram no lint; permanecem os avisos
preexistentes de Browserslist e tamanho de chunks na build.

A bateria inclui regras anteriores e novos casos de privacidade HTTP, busca
paginada, fontes remanescentes, administração delegada e autorrebaixamento.
No MySQL real, a busca inclui 105 usuários de teste, página seguinte, e-mail,
contas inativas e outro tenant; o preview é comparado com fontes reais.
Todos os dados ficam em transação revertida, com conferência de ausência dos
tenants temporários ao fim.

No navegador: concessão por grupo/usuário, edição, preview, cancelamento,
revogação com falha/retry, troca do formulário durante preview, busca com
respostas fora de ordem, paginação, busca com erro/retry, navegação de origem,
Meu acesso por usuário comum e viewport móvel. Rotas HTTP são controladas para
reproduzir instabilidade. Os testes HTTP assinam JWTs de teste e verificam que
parâmetros userId/tenantId não permitem consultar outra identidade.

O workflow `.github/workflows/acl-resilience.yml` inclui os arquivos novos nas
condições de execução e usa MySQL isolado. CI remoto não foi disparado.

## Limites de interpretação

- A prévia é uma fotografia do item selecionado. Hosts e subpastas podem ter
  concessões adicionais. Ela não promete revogação global do usuário.
- Administradores do tenant mantêm o acesso operacional do perfil; remover
  uma concessão ACL não equivale a retirar esse perfil.
- Mudanças simultâneas posteriores à prévia podem alterar o resultado. A
  autorização continua sendo verificada no momento da gravação.
- Meu acesso explica permissões; não garante conectividade, disponibilidade
  do host ou cumprimento de políticas adicionais de sessão.
- Testes de rede nesta bateria usam falhas controladas. Não houve alteração
  de produção nem teste de failover entre múltiplas réplicas.
